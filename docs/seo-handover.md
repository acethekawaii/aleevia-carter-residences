# SEO & Social Sharing — Handover

Everything below is already built into the site. This doc is what **you** do after
deploying to Vercel, plus what to send to push it further.

## What ships now

- **Per-page metadata** — unique title, description, and canonical URL on every
  public route (home, about, contacts, financing, blog, each post).
- **Designed link-preview cards (1200×630)**, auto-generated, shown on Facebook,
  Messenger, Viber, X, and LinkedIn:
  - site default (exterior),
  - `/financing/*` (Pag-IBIG obr Chinabank),
  - every blog post (uses the post's own cover image, randed).
- **Sitemap** at `/sitemap.xml` — includes all blog posts, refreshes hourly.
- **Robots** at `/robots.txt` — allows crawling, points to the sitemap.
- **Structured data (JSON-LD)** — `RealEstateAgent`/local business (address,
  phone, hours, Facebook), `WebSite`, `BreadcrumbList`, and `BlogPosting`.
- **Theme color** + a **Google Search Console verification** slot.

All facts come from `lib/site.ts` — update contact details, hours, and the
Facebook URL there, never in components.

## 1. Set these Environment Variables in Vercel

Project → Settings → Environment Variables (scope: **Production**, and Preview if
you want correct previews). Redeploy after adding.

| Variable | Value | Why |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | `https://aleeviacarterresidences.com` | Makes OG images, canonicals, and the sitemap use the real domain. |
| `GOOGLE_SITE_VERIFICATION` | *(token from Search Console — see below)* | Verifies the site via meta tag. Optional if you verify by DNS. |
| `NEXT_PUBLIC_API_BASE_URL` | *(your blog/concierge API base, incl. `/api/v1`)* | Already used; confirm it's set in Production so the blog + sitemap posts appear. |

## 2. After the domain is live

1. **Confirm** `https://aleeviacarterresidences.com` loads and
   `.../sitemap.xml` shows your pages + posts.
2. **Google Search Console** — https://search.google.com/search-console
   - Add a property. Prefer a **Domain** property (add the DNS TXT record) — it
     covers www/non-www and http/https in one go. Or use **URL prefix** + the
     HTML-tag method: copy the `content` token into `GOOGLE_SITE_VERIFICATION`,
     redeploy, then click Verify.
   - **Sitemaps** → submit `sitemap.xml`.
   - **URL Inspection** → test the homepage → **Request indexing**. Repeat for
     About, Contacts, both Financing pages, and Blog.
3. **Bing Webmaster Tools** (optional, 2 min) — import from GSC, submit the same
   sitemap. Covers Bing + copiloted search.
4. **Refresh the social scrapers** (they cache the old/empty preview hard):
   - Facebook / Messenger / **Viber**: https://developers.facebook.com/tools/debug/
     → paste each URL → **Scrape Again**. (Viber reuses Facebook's OG cache.)
   - LinkedIn: https://www.linkedin.com/post-inspector/
   - X/Twitter: just post a test link — posting re-fetches the card.
5. **Google Business Profile** (biggest local-SEO lever for a property) — create or
   claim it. Use the **exact** name, address, and phone that are on the site so it
   matches our structured data; add the website link and photos. This drives the
   map pack and the knowledge panel.

## 3. Watch for the first 2–4 weeks

- GSC **Pages**: indexed count should climb; investigate "Discovered – currently
  not indexed".
- GSC **Enhancements / Breadcrumbs**: should validate. Spot-check with the
  Rich Results Test → https://search.google.com/test/rich-results (paste a URL).
- GSC **Performance**: impressions, clicks, and which queries you appear for.

## 4. To make it stronger — send these and I'll wire them in

- **Real photography** (exterior, amenities, model units) at the highest
  resolution you have. The cards currently use the in-repo renders; real photos
  convert better and can replace them 1:1.
- **A logo file (SVG preferred).** Enables a proper favicon/app-icon set and a
  real logo in structured data (it currently falls back to the hero photo).
- **Marketing-approved specifics** you're allowed to publish (price-from,
  turnover date, exact unit sizes). Lets me add richer card copy and truthful
  `Product`/`Offer` schema.
- **Any other official socials** (Instagram, TikTok, YouTube) → added to the
  structured-data `sameAs` so Google links them to the brand.
- **Google Business Profile** access (or confirm it exists) for NAP consistency.
- **GA4 / Search Console** access if you want analytics wired and indexing
  monitored.

## Notes for developers

- Cards are generated by `app/**/opengraph-image.tsx` via `next/og`, sharing the
  layout in `lib/og.tsx`. Fonts are vendored in `assets/fonts/` (Satori needs real
  font files); the palette in `lib/og.tsx` is the sRGB conversion of the `oklch`
  tokens in `globals.css`.
- JSON-LD builders live in `lib/schema.ts`, emitted by `components/seo/json-ld.tsx`.
- Blog post cards pull each post's `coverImageUrl`; if it's unreachable they fall
  back to a warm interior, then to the branded emerald canvas — a share never
  renders a broken image.
